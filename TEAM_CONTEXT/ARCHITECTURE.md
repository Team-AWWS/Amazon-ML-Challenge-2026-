# Implemented architecture

Input TSV schema for every source: `entity_id`, `business_name`, `business_address`, `country`. Source 1 (`S1-`) is the reference; Source 2/3 (`S2-`, `S3-`) supply zero or more matches. Training has US and India labels; test additionally has France. Ground truth has `source1_entity_id`, `matched_entity_ids` (comma-separated or empty). Output `matching_results.tsv` has those same two columns; `candidate_pairs.tsv` has `source1_entity_id`, `candidate_entity_ids`. Both outputs contain one tab-delimited row per test Source 1 ID. Candidate IDs are the exact set scored, and predictions must be a subset.

Implementation is in `code/business_entity_resolution/src/pipeline.py`. It case-folds and normalizes Unicode, removing Latin accents while preserving Indic/non-Latin combining marks, punctuation boundaries, and original source text in the input files. A disk-backed SQLite target index stores normalized Source 2/3 names and addresses; country/name and country/address B-trees serve exact routes. FTS5 and its vocabulary metadata serve optional rare-token routes. Both train/test indexes are derived solely from supplied records and are **not in Git**.

The primary `rare_both` retrieves up to six exact-name and six exact-address targets per source and country. If fewer than eight unique exact candidates exist, it selects one address token and one name token with corpus document frequency 2–1,000 and queries each target source for at most six records per route. It deduplicates IDs and caps the list at 36 (observed test max 31). The fallback `narrow` uses exact routes only. Broad OR/BM25 FTS was abandoned for runtime.

Every retrieved candidate receives a deterministic score combining name token overlap, address token overlap, character trigrams, and address-number agreement/conflict. Score cutoff is 0.65 primary / 0.68 fallback, chosen on dev. There is no fitted classifier, external enrichment, pretrained model, or GPU. The writer stages `.part` files before replacing both output TSVs on successful completion; an interruption between replacements can still make a mixed pair, so hashes and complete validation are mandatory.

Metric: entity-level macro F0.5, averaged across Source 1 entities. For non-empty truth, score is `5 TP / (5 TP + 4 FP + FN)`; empty truth and empty prediction score 1, while empty truth with any prediction scores 0. Candidate-link recall is separate: retrieved true links divided by all true links. Split by stable normalized Source 1 name/address identity hash, not pair rows: train 2,118,511, dev 44,098, holdout 44,212. Exact identity groups do not cross partitions, but similar related records can.
